## Question

Build milestone M4: the monochrome MapLibre component and map tab (frame 1f),
plus the static landing teaser that replaces M1's placeholder.

## Resolution

- **Map tab (1f)**: MapLibre GL on a hand-written monochrome style over
  OpenFreeMap tiles (basemap ticket's recommendation — free, no key, no
  request limits; attribution rendered). Routes are `@turf/great-circle`
  arcs pinned to 7.3.1, width scaled by how often the route was flown;
  airport dots are sized by activity with hover detail. The view auto-fits
  the current filter.
- **Two filter axes only**, as the map ticket required: the global year param
  plus an airline rail capped at the top 6 carriers. Footer counts (airports
  shown / unique routes / countries) restate what is filtered, so the picture
  stays interrogable.
- **Landing teaser**: inline SVG computed at render from the canonical demo
  dataset — the same great-circle maths, no tiles, no client JS, nothing to
  ship. The wireframe's rule (never a live map instance on the marketing
  page, for cost and LCP) is kept without needing the Playwright
  screenshot step the research proposed; that remains an option if the
  teaser ever needs basemap fidelity.
- `preserveDrawingBuffer` is set at map creation so M5's "Save as image" can
  read the canvas.

## The one real trap: MapLibre v6 in Next dev

MapLibre v6 is ESM-only and spawns its tile worker as a **module Worker**
resolved relative to its own bundle. Next's dev server answers that URL with
HTML, so the worker never starts — and the failure is silent and confusing:
the map object constructs, controls and attribution render, the canvas gets a
WebGL context and paints the style's background layer, but no tile is ever
parsed and `isSourceLoaded` stays false. There is no error event.

Fix: `scripts/copy-maplibre-worker.mjs` copies `maplibre-gl-worker.mjs` and
its shared chunk into `public/maplibre/` (wired to `predev`/`prebuild`), and
the component calls `setWorkerUrl` to point at it.

Two smaller ones found the same way: the style referenced a
`globallandcover` source layer OpenFreeMap does not carry (OpenMapTiles has
no global land polygon — the background *is* the land, as Positron does it),
and `next/dynamic` around the client component left the browser without the
module entirely.
